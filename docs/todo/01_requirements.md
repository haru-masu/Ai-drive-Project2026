# TODOアプリ V1 要件定義書

## 1. 開発目的

既存のExpress・TypeScript・EJS環境を使用して、TODOを登録・一覧表示・更新・削除できるWebアプリを開発する。

データベースにはNeon PostgreSQLを使用し、GitHubでソースコードを管理してVercelに公開する。

## 2. 対象範囲

### 対象機能

- REQ-01：TODO一覧取得
- REQ-02：TODO新規登録
- REQ-03：完了状態の部分更新
- REQ-04：TODO削除

### 対象外の機能

V1では以下を実装しない。

- ユーザー認証
- 優先度設定
- TODOの絞り込み
- タイトルの更新

これらのうち優先度と絞り込みはV2で実装する。

## 3. 使用技術

| 項目 | 使用技術 |
|---|---|
| フロントエンド | HTML・EJS・JavaScript |
| バックエンド | Node.js・Express・TypeScript |
| データベース | Neon PostgreSQL |
| 通信 | Fetch API |
| ソースコード管理 | GitHub |
| 公開環境 | Vercel |

既存のトップページ `/`、DB接続確認API `/api/db-check`、商品一覧 `/db-sample` は維持する。

TODO画面は `/todo` に配置し、APIは `/api/v1/todos` を使用する。

## 4. 機能要件

### REQ-01：TODO一覧取得

**操作**

TODO画面を開くと、登録済みのTODOを一覧表示する。

**入力**

GET `/api/v1/todos`

**結果**

- 登録済みTODOを取得できる
- データが0件の場合、HTTP 200で `{"data":[]}` を返す
- 画面には「TODOがありません」と表示する

**エラー**

DB接続などに失敗した場合はエラーを通知する。

**受け入れ条件**

登録済みのTODOが一覧に表示され、0件の場合もエラーにならず空の状態を表示できること。

**確認方法**

APIにGETを送信し、画面表示とレスポンスを確認する。

### REQ-02：TODO新規登録

**操作**

タイトルを入力し、登録ボタンを押す。

**入力**

POST `/api/v1/todos`

- タイトルは必須
- 前後の空白を除去する
- 文字数は1〜100文字

**結果**

- 正常なタイトルを登録できる
- 登録されたTODOが一覧に反映される
- 新規TODOは未完了状態で作成される

**エラー**

タイトルが未入力、不正な形式、文字数制限違反の場合はエラーを返し、登録しない。

**受け入れ条件**

1〜100文字の有効なタイトルを登録でき、不正な入力ではデータが追加されないこと。

**確認方法**

正常なタイトル、空白のみ、101文字以上のタイトルを入力して確認する。

### REQ-03：完了状態の部分更新

**操作**

TODOのチェックボックスを操作する。

**入力**

PATCH `/api/v1/todos/:id`

- IDは1以上の整数
- 完了状態は真偽値で指定する

**結果**

- 未完了から完了へ変更できる
- 完了から未完了へ戻せる
- タイトルなど、対象外の項目は変更しない

**エラー**

不正なIDや存在しないTODOを指定した場合、適切なエラーを返す。

**受け入れ条件**

指定したTODOの完了状態だけを変更でき、ブラウザ更新後も変更が保持されること。

**確認方法**

チェックボックスを操作し、APIの結果とDBの保存状態を確認する。

### REQ-04：TODO削除

**操作**

TODOの削除ボタンを押す。

**入力**

DELETE `/api/v1/todos/:id`

- IDは1以上の整数

**結果**

- 指定したTODOを削除できる
- 削除後、一覧から対象が消える
- 削除成功時はHTTP 204で本文を返さない

**エラー**

不正なIDや存在しないTODOを指定した場合、適切なエラーを返す。

**受け入れ条件**

指定したTODOだけを削除でき、削除後の一覧に表示されないこと。

**確認方法**

削除前後のAPIレスポンスと一覧画面を比較する。

## 5. 共通のデータ仕様

データベースでは `todo_tasks` テーブルを使用する。

| カラム | 内容 |
|---|---|
| id | TODOの識別番号 |
| title | タイトル |
| is_completed | 完了状態 |
| created_at | 作成日時 |

- IDは1以上の整数とする
- タイトルは前後の空白を除去し、1〜100文字とする
- 新規登録時の完了状態は未完了とする
- JSONのキーはcamelCase、DBのカラム名はsnake_caseとする

## 6. 共通のAPI・エラー条件

APIではHTTPステータスコードとJSONを用いて結果を通知する。

| ステータス | 内容 |
|---|---|
| 200 | 取得・更新成功 |
| 201 | 登録成功 |
| 204 | 削除成功（本文なし） |
| 400 | リクエスト形式・IDなどが不正 |
| 422 | 入力内容が要件を満たさない |
| 404 | 対象TODOが存在しない |
| 500 | サーバー内部エラー |
| 503 | DBなどのサービスが利用できない |

成功時JSONとエラー時JSONの厳密な共通形式は、別途指定される「第6章 V1共通仕様」と照合して確定する。

## 7. 画面要件

TODO画面 `/todo` には以下を配置する。

- TODO入力欄
- 登録ボタン
- TODO一覧
- 完了状態を切り替えるチェックボックス
- 削除ボタン
- エラーメッセージの表示欄
- 0件時の「TODOがありません」という表示

画面からFetch APIでバックエンドにアクセスし、ページ全体を再読み込みせずにデータを更新する。
